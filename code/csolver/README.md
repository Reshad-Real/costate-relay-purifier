# Embedded components

| File | Purpose |
|---|---|
| `mpc_solver.h/.c` | Exact branch-and-bound solver for the blocked discrete MPC (C99, float, no malloc). Define `MPC_DEPLOYED_DIMS`, or build for ESP32, to size the workspace for 3 zones, 6 pollutants, 4 duties, N=30, Nu=6 (about 14 kB). |
| `bench.c` | PC benchmark used for the computation results (`experiments/e6_timing.py` compiles and runs it). |
| `esp32_bench/` | On-target timing sketch. Copy `mpc_solver.c/.h` into the folder before building. |
| `rollout_law.h` | Rollout costate law (Eq. 11), the recommended controller for microcontroller deployment. Recomputes its costates backward from the end of the day at each decision (no stored table): at most K·NP·NZ² = 32 400 multiply-adds per decision. |
| `rollout_params.h` | Parameters for the nominal model, generated by `experiments/export_rollout.py`. The script also checks the C law against the Python controller's decision rule on 3000 random states, drives, steps and budgets (`results/e6/rollout_c_check.json`). |
| `costate_law.h` | Stationary costate band law (CL-s), kept for comparison. |
| `costate_params.h` | Parameters for CL-s, generated by `experiments/export_costate.py` (checked on 2000 random states). |
| `esp32_footprint.sh` | Compiles the solver and both laws with the ESP32 toolchain and writes `results/e6/esp32_footprint.json` (code and data sizes; no board needed). |

Measured with the ESP32 Arduino core 3.3.7 (xtensa-esp-elf-gcc 14.2, `-Os`): rollout law 1026 bytes of code and
2080 bytes of parameters; stationary law 519 bytes; solver 3.5 kB of code and 13.6 kB of workspace. On-target timing has
not been measured.

## Integrating the rollout law into the CCU firmware (not yet done or tested on hardware)

1. **Gateway (DAG.ino).** Forward the per-node readings (three zones × six pollutants), averaged over
   60 s, instead of the per-pollutant maximum that `aggregateAndSendToFan()` currently sends.
2. **Drive estimate.** Compute the persistence drive estimate `d[p][j]` from consecutive averaged readings and the
   applied duty, as in `aqmpc/forecast.py` (`OnlineDrive`, mode `persistence`).
3. **CCU (CCU.ino).** Every 60 s, replace `calculateFanSpeed()` with
   `rollout_duty(&ROLLOUT_PARAMS, x, d, k, rem)`, where `k` is the step since 07:00, `x[p][j]` holds the zone
   averages in the units of the paper and `rem` is the remaining energy budget in Wh (`INFINITY` without a budget).
   Map the returned index to the PWM values 0/204/230/255.
4. **Fallback.** Keep the relay as a fallback in case gateway data are lost.
5. **Parameters.** Re-generate `rollout_params.h` after identifying the model on site (Appendix A of the
   manuscript).
